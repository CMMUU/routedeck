# Serylane v0.7.6

## 订阅新增入口统一

- 「订阅」成为添加订阅地址的唯一入口，避免概览、配置和订阅页面重复出现相同的新增表单。
- 概览中的引导和空状态直接前往订阅页；配置页继续保留本地 YAML 导入、配置管理与版本回滚，不把本地配置功能移除或改成远程订阅。
- 新增表单采用紧凑布局，突出主要输入与提交操作，高级选项按需展开；说明和错误信息仍保持清晰可读。

## 添加、选用与后续任务分开说明

- 通过「添加后选用」明确选择是否选用新订阅。已有选用配置时，该选项默认不勾选，避免新增订阅时无意替换当前选用项。
- 添加成功后定位并聚焦已保存的订阅卡片；如果等待时已切页或移动焦点，则不抢回焦点。添加失败时保留表单草稿，方便修正后重试。
- 重复地址不新增、不悄悄刷新；明确勾选「添加后选用」时，选用该订阅已经保存的版本。
- 检查记录写入失败会单独提醒，不把已保存的订阅误报为添加失败。
- 可选的 OpenAI 灾备生成任务单独显示状态。后续生成失败不把已经保存的订阅误报为添加失败，也不要求重复导入该订阅。
- 「已添加」「已选用」描述的是配置状态，不代表节点可用、真实请求已经通过或 Codex 已建立连接。

## 保持现有使用与升级边界

打开新增入口不会自动启动 Mihomo、修改系统代理／TUN，或接入 Codex。主「启动」继续使用 v0.7.5 的系统代理流程，明确的 TUN 入口仍保持独立。路由默认关闭，保存设置、启用服务和接入 Codex 仍是独立操作。

继续使用 Serylane 展示品牌及蓝色 S 图标。安装名称 `RouteDeck`、`routedeck` 主程序、应用与 helper 标识、数据目录、GitHub/Gitee 更新地址、`RouteDeck_…` 安装包命名和现有更新签名公钥均保持不变；本版本不重写历史标签或 GitHub 发布附件。

自动更新仍优先使用可用的国内渠道，并保留 GitHub 备用。国内镜像遵循已确认的「只保留最新一个正式版本附件」策略，历史源码、标签和 GitHub 发布记录保留；具体清理和同步结果以本次工作流执行及公开附件回验为准。

## 验证与发布状态

本说明对应 v0.7.6 的源码变更。测试结果、安装包公开状态和国内镜像可用性需分别验收，不能由版本号或发布说明的存在推断已经完成。正式可用版本以 Release、更新清单和实际附件核对结果为准。

自动化测试不等于真实网络或长期会话验收；Windows TUN 仍为实验性功能，兼容路由与灾备策略不保证永不断线，切换节点不能续接已中断的数据流。检查和下载更新不会安装或重启应用；安装仍需用户确认，安装及重启可能中断连接，请避开重要会话。
