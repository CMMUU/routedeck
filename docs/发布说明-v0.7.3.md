# RouteDeck v0.7.3

## 磨砂玻璃界面

- 按确认的设计统一应用内磨砂背景、单色线性图标、导航、表单、按钮、开关及圆角滚动条，减少重复边框与彩色装饰。
- 保留 11 个菜单、已有状态信息及安全确认流程；浅色、深色、深紫和窄窗口使用一致的视觉层级，保持中文正文可读。
- 完善键盘焦点、弹窗取消与焦点返回，并提供减少透明度、减少动效及高对比度降级。保留 Windows 原生窗口习惯；应用内玻璃效果不代表桌面背景透底。

## 紧凑订阅卡片

- 订阅列表改为紧凑卡片，集中展示订阅名称、启用与更新情况，以及服务商提供的流量用量、总量和到期信息，便于同时查看多个订阅。
- 流量和到期数据读取服务商的 `subscription-userinfo` 响应头，不将本机实时速率或连接状态当作套餐用量。
- 订阅内容未变化、返回 HTTP 304 时仍可刷新响应头中的用量等元数据，不为相同配置重复生成内容版本。
- 服务商未提供或未完整提供用量、总量或到期信息时，显示对应的未提供提示，不将缺失值当作零用量、无限流量或永久有效。用量信息随订阅更新获取，不是服务商账户的实时账单。

## 可选的独立路由

- 新增“路由”页面，默认关闭，仅针对模型 API 提供本机转发入口。保存设置、启动服务、接入 Codex 仍是三个独立操作。
- 提供 HTTP/SSE 兼容模式与原生 WebSocket 模式。兼容模式减少对 WebSocket 的依赖，但仍需要稳定的网络出口；部分实时能力需要在新会话中验证。
- 接入前备份配置，保留登录信息，不修改 `auth.json`，不接管整个应用或系统代理，不强制关闭已运行的程序。接入配置写入成功不等于新会话已经生效。
- 保留进行中请求保护、配置冲突检查与恢复确认；其他程序更改接入配置后，不覆盖冲突内容。恢复后如原入口依赖 CC Switch，仍需其服务正常运行。

## 更注重持续稳定的 OpenAI 灾备

- 按近期基础检查与可确认归属的模型流样本评估节点，健康的当前节点保持使用。连续故障后进入冷却期，恢复还需连续检查通过，减少反复切换。
- 切换面向后续新连接，不主动清空正常连接，不自动重发模型请求。已经中断的数据流无法通过换节点无缝续接，兼容模式与灾备策略均不承诺永不断线。
- 基础 API 检查和真实模型完成情况分开显示；预期 HTTP 401 只说明基础可达性，不作为完整模型验证。没有模型样本时明确提示；无法确认节点归属、用户取消或原生隧道关闭不直接算作节点故障。

## 更新与验证边界

“设置 → 软件更新”继续使用自动国内优先策略：选择最高稳定版本，同版本优先 Gitee，GitHub 备用。跨渠道下载回退仅接受版本、大小、摘要及签名一致的包。Gitee 仅保留最新 1 个正式版本的镜像附件；GitHub 历史、两站源码与标签保留。

正式发布需通过前端与原生回归、版本一致性检查、六平台签名构建和附件校验；新增订阅及路由测试纳入 CI 与发布工作流。隔离预览和自动化测试不代表真实 WebView、服务商订阅或 Codex 连接已经验证，也不代表所有网络环境下均不会重连。

本说明本身不表示版本已经发布、国内镜像已经同步或本机已经安装。请以各渠道实际清单与附件校验结果为准。检查和下载更新不停止代理；安装仍由用户确认，安装及重启可能短暂中断连接，请避开重要会话。应用身份与数据目录保持不变，更新签名不等于 Windows Authenticode 签名或 Apple 公证。
