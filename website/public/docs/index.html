Serylane / 使用文档

从清楚了解开始。

Serylane 是管理你已有订阅与配置的独立桌面客户端，不提供代理节点或订阅服务。

快速开始

  1. 前往下载区域，选择系统与处理器架构，从项目的 GitHub 或 Gitee 发布页获取对应安装包。以发布页实际附件为准；没有对应附件时，不要下载其他架构的包代替。
  2. 根据对应版本的发布说明核对功能和平台要求；源码中的功能不代表已经进入当前安装包。
  3. 打开客户端，通过「订阅 → ＋ 添加订阅」添加自己的 Clash Meta / Mihomo YAML 订阅；本地 YAML 请在「配置」页面导入。订阅地址通常包含访问凭据，不要公开分享。
  4. 已有当前配置时，添加订阅默认不选用；只有勾选「添加后选用」才会替换当前配置。添加或选用不会自动启动代理，需要连接时再点击「启动」。使用系统代理或 TUN 前，先关闭其他代理客户端的同类接管功能，避免相互覆盖。
  5. Codex 本地路由是可选功能，不是日常代理使用的前置条件。没有需要时，保持默认关闭即可。

选择 Mac 芯片版本

macOS 安装包分为 Intel 芯片（x64） 与 Apple 芯片（M 系列，ARM64）。打开苹果菜单 →「关于本机」：显示 Intel 处理器时选 Intel 版；显示 Apple M 系列芯片时选 Apple 芯片版。不要仅凭 macOS 版本或机型年份猜测。

下载最新 Intel 芯片版 · 下载最新 Apple 芯片（M 系列）版。每次点击都会重新核对最新正式版；国内没有对应包时转到 GitHub 同版本包，不以另一种芯片的包代替。

理解订阅用量

订阅卡片展示服务商返回的上传、下载、总套餐流量与到期信息。这些数据是订阅响应中的采样，不是客户端实时统计的账单。

未提供的字段会明确标注。刷新失败时，客户端可能保留上一次成功采样；请同时留意更新时间与错误说明。缺失数据不等于零用量、无限套餐或永久有效。

选择适合的代理方式

  • 系统代理：供遵循系统代理设置的应用使用，不保证覆盖全部程序与连接协议。
  • 程序代理：为支持代理参数或环境变量的应用提供启动入口。不会强制关闭已有实例；旧实例可能忽略新启动参数，需要你方便时自行退出再启动。
  • 本地路由：仅对支持的 Codex 模型 API 提供独立入口，不代表接管整个 Codex 应用，也不保证登录、遥测或其他连接统一走该入口。

Windows TUN：实验性功能

目前不将 Windows TUN 描述为已完成日常网络接管验收。管理员会话与内核进程生命周期已实现，但真实路由、DNS、停止和异常退出后的网络恢复仍需独立验收。

需要试用时，先保存工作并阅读当前版本发布说明。Windows 使用管理员会话：从托盘退出客户端后，自行选择「以管理员身份运行」。普通系统代理不要求管理员会话。

停止或退出时，客户端会按自身状态尝试恢复网络设置；关闭主窗口通常只是隐藏到托盘。系统代理恢复会核对控制权，避免覆盖后来由其他客户端设置的代理。不要同时开启多个客户端的系统代理或 TUN。

如果恢复失败，不要反复切换多个接管工具。先记录当前错误与状态，停止相关接管，再核对系统代理和 DNS 设置。遇到不明确的网络状态时，保留日志并通过项目问题追踪反馈，分享前删除订阅链接、令牌和个人信息。
